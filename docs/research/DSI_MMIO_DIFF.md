## 2. Scope

- **Instrument (D-01):** additive debugfs snapshot node `i915_dsi_regs` in the
  CI-built i915 (patch on branch `instrument/d330-dsi-dump`). Write side
  (`echo 1 > …`) walks the locked MMIO ranges once into a frozen kernel buffer;
  read side (`cat`) emits it. Zero register writes, no mode changes. DSI-block
  reads gated on the BSpec machine-hang rule (DSI access with the PLL in a bad
  state can hang the machine) — the gate never tripped: **zero `# SKIPPED`
  markers on any of the four arms**. Post-47-review the gate also covers the
  PHY walk (0x160000-0x164000) and the PHY-area overlay reads (commit
  `b753d39` on `instrument/d330-dsi-dump`, not yet in a deployed kernel):
  with the PLL off the node emits a second marker, `# SKIPPED: DSI PLL off -
  PHY reads skipped`, and the diff tooling keys each marker to exactly its
  own range. The four registered captures predate this — all taken with the
  PLL enabled, so the registered evidence is unaffected. Node resolved across
  `/sys/kernel/debug/dri/*/i915_dsi_regs` (card1/dri/1 drift, 47-03 deviation 1).
- **Trigger:** manual echo per arm, identical code path both arms, inside the
  inhibit-held window; snapshot freezes values at trigger time.
- **Locked scope (D-02):** the 5 ftrace-known ranges plus the full DSI
  port/transcoder block:

| range | words | content |
|---|---|---|
| 0x6b000-0x6c000 | 1024 | DSI ports A..C, INTR, DEVICE_READY, MIPI_CTRL (RO status) |
| 0x160000-0x164000 | 4096 | BXT/GLK DSI PHY (MIPIO clock/control + DPHY ports) |
| 0x46000-0x47000 | 1024 | clock control, DE PLL, DSI PLL |
| 0xc7200-0xc7400 | 128 | legacy PPS |
| 0x138000-0x139000 | 1024 | GT DISP PWRON / MIPIO_RST_CTRL / GT PM |

  7,296 registers per arm. Parse summary of the canonical pair: **7296 records
  per arm, 0 warnings, 0 state rows** — every range readable on both arms, so
  no second capture pair was needed (D-04: ambiguity would have scheduled one).
- **Dump format:** `# RANGE <lo>-<hi> (<N> words)` headers, `0x<off>=<8-hex>`
  records, `# NAMED OVERLAY` section (name/address/bit-decode rows),
  `# SKIPPED: DSI PLL off - DSI block reads skipped` / `# SKIPPED: DSI PLL
  off - PHY reads skipped` marker contract (never fired). Two all-ones words
  are constant across all four arms (0x6b008, write-only interrupt-enable;
  0x138080, GT block) — constants, not diffs.

### 4.4 Structural conclusion from the 3-way contrast

In the broken state **every static config register is byte-identical to fresh
boot**: DSI PLL/clock block 1024/1024, PHY readable portion identical apart
from the two operational rows, legacy PPS 128/128, GT block 1019/1024. The
broken-state deltas are **DSI operational/status registers only** — the
resume path ran (prior evidence: it runs the full correct cold MIPI sequence
and drives the panel GPIOs, DISPLAY_RESUME_CCS_MODIFIER.md:100-152) and left
the link in a degraded, timeout-marked condition, while the working resume
left it exactly at the boot set. The kernel-side software state was already
proven byte-identical working-vs-broken in v8.0 (NO_CLEAN_FIX_PROOF.md §3);
this dump now proves the same for the hardware's static configuration, and
isolates the difference to operational link state.

## 5. Mechanism claim (D-05): the ONE testable claim

**Claim: the broken resume path fails to re-reach the GOP's boot-time DSI
operational state; the working resume path re-reaches it.** In claim form:
**GOP sets the DSI operational state X=Y at boot — 0x160018=00000115,
0x6b010=003fffff, 0x6b044=0000001d, 0x6b080=09051003, 0x6b088=0022000f,
0x6b098=09051003, 0x6b094=00000001 (boot_dsi_regs.txt:1033, 6, 19, 34, 36, 40,
39); the broken resume leaves X=Z — 0x160018=00000001, 0x6b010=0000b8ea,
0x6b044=0000001e, 0x6b080=0a051003, 0x6b088=0014000c, 0x6b098=0a051003,
0x6b094=00000000, with the link timeout-marked (0x6b004=40280000)
(broken_dsi_regs.txt:1033, 6, 19, 34, 36, 40, 39, 3) — and every static config
register identical to boot.** The working resume re-reaches X=Y byte-for-byte
(session-1 pair, §4.2). The mechanism is therefore **the operational state the
enable path reaches or fails to reach** — a sequencing/state property, never a
set of register values.

**Testability (Phase 48):** make the resume path replicate the GOP boot-init
step as a sequence — reach the state, do not patch values — then re-dump at
wake with the in-baseline node and judge by eyes-on. Prediction: the panel
lights only if the at-wake dump shows the operational rows equal to the boot
set (and the timeout status bits unset). Falsification condition: if the
sequencing reaches X=Y, holds at wake, and the panel still stays black, the
mechanism is below host MMIO (panel TCON side) and Phase 48 pivots to the
next instrument in §6.

### 5.1 Falsification result (phase 48, 2026-10-15): the branch FIRED, stronger than predicted

The phase-48 iteration ladder (ledger rows 30-32) ran three DMI-gated
sequence-state candidates — (1) fresh-device-state branch (retained
ULPS_STATE_MASK/DEVICE_READY cleared before the cold-boot probe, reload
ordering), (2) full panel power cycle with reload-scale hold at the top of

each tested with one user-authorized rtcwake session; verdicts verbatim:
"Still black", "black but lit", "Black but lit". In all three the at-wake
operational signature stayed at X=Z (never moved toward X=Y).

Then the decisive capture became possible (the dump node was fixed to
survive an unbind/bind in iteration 3's build): the **working-lit state**
(panel restored via the reload workaround, node still alive) is
`docs/dumps/re_kit/reload_lit_dsi_regs.txt` (sha 593739ff…0e2c).
Compared against the broken-wake arm
(`it3_resume_dsi_regs.txt`, sha 6d35ffab…b9a3):

- **The entire diff = 5 rows, all in the GT block: 0x138070/0x138074
  (monotonic counters, excluded-volatile) and 0x138108/0x13819c (GT PM

- Zero DSI, DSI-PHY, PLL/CDCLK, PPS, or MIPIO rows differ between the
  state that SHOWS THE IMAGE and the state that is BLACK.

Conclusion (supersedes the §5 claim's premise that X=Y vs X=Z
discriminates): **no host MMIO state distinguishes working from broken at

or enable-path sequence can fix what no register state discriminates; the
iteration ladder stops here (3 of ≤5 used) per the ledger's disproof
discipline. Full closure: `NO_CLEAN_FIX_PROOF.md` §7. Next instrument: §6
plus the §7 pivot note below.
