# Plan 50-01: echo-2 DCS ID-read instrument (kernel node + CI build)

<objective>
Extend the existing `i915_dsi_regs` debugfs node (per the 50-CONTEXT Instrument
Behavior locked decisions) with an `echo 2` trigger that performs the unchanged MMIO
walk and then issues five DCS/generic reads against the live DSI device — 0x04
(Get Display ID), 0xDA / 0xDB / 0xDC per-byte fallbacks, and one generic register
read — LP mode, VC 0, port A, appended as an annotated `# DCS ID READ` section.

-EOPNOTSUPP for all READ types), so extending this node is the only software path.
Purpose: this is the instrument the whole phase (and Phase 51's E3 discriminator)
depends on; everything downstream consumes its output.

Output: extended `patches/d330_dsi_dump.patch`, CI grep-proofs, and a green CI run
producing the echo-2 kernel .deb with recorded sha256.

Commit discipline (v10.0 process rule): no code/data commits in this plan — code
ships via /gsd-ship; planning-doc changes only via gsd-tools.
</objective>
