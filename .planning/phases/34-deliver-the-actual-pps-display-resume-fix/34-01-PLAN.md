# Phase 34 Plan 34-01: Deliver the Actual PPS / Display Resume Fix

## Objective

Make the recommended install path honest and internally consistent (audit C4/N3/M17): ship the module as a real DMI-matched banner/breadcrumb (research Finding Q1: no notifier event between panel-off and panel-on, so an out-of-tree module cannot enforce TCON discharge timing), delete the echo-only resume service, add an optional `--kernel-src` clamp-patch step gated by `patch -p1 --dry-run`, keep `video=efifb:nobgrt` (research disproved the removal premise), add the two documented `panel_orientation` tokens, harden `dkms.conf`, fix the `test_resume_loop.sh` `set -e` arithmetic blocker, and correct README/CHANGES_AUDIT claims so they match observed behaviour.

## Research Deviations (auditor-visible)

1. **`video=efifb:nobgrt` KEPT, not removed.** CONTEXT/ROADMAP called it "not a documented efifb option"; research Finding 3a proves it is parsed in `drivers/video/fbdev/efifb.c` (`efifb_setup`, v5.15–6.6). Removing it would regress the BGRT-logo fix the file comment promises. The docs premise is corrected instead.
2. **PM handler = option (b), not (a).** Research Q1 (kernel `suspend.c` v6.6) shows `PM_SUSPEND_PREPARE` runs with the panel ON and `PM_POST_SUSPEND` after re-energise; no notifier event sits between panel-off and panel-on, so option (a) cannot deliver the clamp. Module becomes an honest banner; the clamp is delivered only by the Option 2 kernel patch.
