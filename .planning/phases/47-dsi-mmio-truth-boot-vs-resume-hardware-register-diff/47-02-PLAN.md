  - Two identical dumps → zero differing rows, per-range counts only; exit 0

  - Malformed line (not matching the record regex) → counted in a parse-warning line, never parsed as data
  </behavior>

  <action>
  Write `scripts/dsi_mmio_diff.sh` (POSIX-ish bash, `set -euo pipefail`, executable
  100755) with interface: `dsi_mmio_diff.sh <boot_dump> <resume_dump> [-o OUTFILE]`
  plus `--selftest`.

  1. Parser: read each dump; track line numbers; collect records only from lines
     matching the record regex `^0x[0-9a-f]+=[0-9a-fA-F]{8}$` (the 47-01 format
     contract guarantees range-walk lines match and named-overlay lines do not);
     anything else inside a range section counts as a parse warning. Emit a
     machine-readable parse summary (records per arm, warnings count).
   2. Range state detection per arm, keyed by the section header lines (hardened:
      a zero-record section can never classify `readable`):
      - a `# SKIPPED: DSI PLL off` marker present AND the section absent or present
        with zero records → arm state `skipped-pll-off` (47-01 emits the marker
        INSTEAD of the `# RANGE` header for a PLL-off DSI section, so both shapes
        mean the same thing);
      - section present with zero records and NO skip marker → `parse-warning`
        state row (malformed dump; 47-01's contract makes this unreachable, so it
        must not silently classify `readable`);
      - section present with records, but >90% of them 0xffffffff → arm state
        `unreadable-0xffffffff`;
      - else arm state `readable`.
     Any range whose two arm states differ or both read non-readable produces ONE
     state row (`STATE` verdict) instead of per-register rows.
  3. Join: sort records by offset on both sides, join on offset. For each offset:
     values equal → per-range identical counter; values differ → row.
  4. Exclusion table (in-script array; the canonical table 47-04 mirrors):
     per-range exclusion entries as offset patterns + reason strings, minimum set:
     0x6b004/0x6b804 + INTR_STAT section siblings 0x6b090/0x6b094 group → reason
     `interrupt status (write-1-to-clear), volatile`; 0x6b118-0x6b137 and 0x6b064/
     0x6b068/0x6b074 group → reason `RX/GEN FIFO, pop-on-read side effect`;
     0x6b138 → `read-valid flag, volatile`; 0xc7200 → `PPS sequence state,
     timing-volatile`; pipe scanout/surface register words → `compositor-volatile
     surface state`; the DC-state/RC6 counter words → `monotonic counters, not
     config`. Each excluded row still prints (offset + both values + reason +
     verdict `excluded-volatile`) — excluded means de-prioritized for the claim,
     never hidden.
  5. Row emission (markdown, one table): columns `offset | boot | resume | verdict |
     citation`. Verdict vocabulary: `differs`, `excluded-volatile`, `state`,
     `parse-warning`. Citation = `boot_dsi_regs.txt:<line>` / resume file name +
     line, taken from parse-time line tracking (this is the D-07 evidence format
     the DIFF doc will quote). A trailing summary block: per-range identical
     counts, exclusion counts, state rows.
  6. `--selftest`: write two tiny embedded fixture dumps to a mktemp dir (covering
     the <behavior> cases above), run the join/classification on them, assert the
     expected row set (exact offset list + verdicts), clean up, exit 0 only if all
     assertions pass. The selftest is the task's automated proof — no hardware, no
     real captures needed in wave 1.
  7. Name lookup: accept an optional mapping file argument later (47-04 may pass a
     names file produced from the tree grep); without it, rows show offsets only.
  </action>
