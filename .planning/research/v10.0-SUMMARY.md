# v10.0 Research Summary

Four parallel researchers (ecosystem mode). Full reports in the files above;
this file carries only the load-bearing deltas.

## The pivot: block-55 closed, DCS read opened

- VBT block 55 = `BDB_COMPRESSION_PARAMETERS_OLD` (BDB 198-212; ours = 212).
  Decoded locally from `docs/dumps/re_kit/runtime_vbt.bin`: DSC 1.1 params,
  **no panel/TCON data**. The v9.0 "block-55 undecoded" mystery ends as a
  negative result.
- TCON identification is still software-only-viable via a **DCS ID read**
  (mipi_dsi_dcs_read → intel_dsi_host_transfer RX path; BTA enabled in VBT
  block 52): extend `i915_dsi_regs` with a trigger mode doing DCS
  0x04/0xDA/0xDB/0xDC, captured boot (X=Y) vs black-resume (X=Z).
- Panel glass = AUO (VBT block 42 PnP ID 0xaf06, 800x1280); Lenovo FRU
  5D11A20220 ("LCD MODULE H 82H0 10.1 HD Touch"); bare-glass model still open
  until the DCS read.
- Corrected decode: `0x6b004=0x40280000` = SPL_PKT_SENT | HS_TX_TIMEOUT |
  LOW_CONTENTION (LP_RX_TIMEOUT NOT set) — §6 label in DSI_MMIO_DIFF needs a
  correction note. Signature = "HS video stream never accepted by panel".

## Keep-panel-powered = the new fix ladder (inverse of rows 30-32)

- Suspend power-off = 3 VBT seqs + 1 DCS in `intel_dsi_post_disable()`
  (vlv_dsi.c: DISPLAY_OFF :901, ASSERT_RESET :926 GPIO160, POWER_OFF :929
  GPIO144) + `intel_dsi_disable()` :842/:853. Host MMIO cannot survive (DC9
  unconditional); panel-side rails CAN be held.
- Ladder: E1 skip panel-side teardown at suspend → E2 warm-resume enable
  (skip POWER_ON + INIT_OTP when keep-hot flag set) → E3 DCS rail-survival
  discriminator. All DMI-gated 82H0, one per CI iteration, success =
  X=Y held at wake + eyes-on.
- Chrome OS shipped no such quirk (chromeos-5.4/5.15 verbatim mainline) — no
  precedent to copy, and Windows re-inits per-S3 via direct TCON programming
  (which keep-hot bypasses the need for).

## Hardware instrument (the buy)

- **Kingst LA5016, ~$238** — the only cheap analyzer with a built-in MIPI-DSI
  LP decoder (KingstVIS). DSI HS (~1 Gbps/lane) is NOT cheap-decodable; loss
  accepted because the panel-init DCS sequences run in LP mode (~25x
  oversample at 500 MS/s). PMIC I2C bus 6 (rails GPIO 144/160/145) is the
  second probe target. Physical: FPC breakout + FFC extension (~$5-15),
  empirical pin ID (no official 82H0 schematic).
- Validate the KingstVIS MIPI-DSI LP decoder in free demo mode BEFORE buying.

## Self-healing safety net (ships regardless of fix outcome)

- **No machine signal distinguishes image from black** (proven v9.0 chain) —
  detector is the user's eyes: deliberate hotkey (Plasma 6.1+ "Command or
  Script" shortcut) → `/usr/local/bin/d330-blackguard --trigger` → beeps →
  10 s countdown (pause on typing, Esc cancels) → `systemctl reboot`.
- Hook: `/usr/lib/systemd/system-sleep/` post-phase detached child; guardrails
  survive a wedged session (root evdev reads, no GUI dependency).
- **Must stand down the old `lenovo-d330-display-resume.sh` hook**
  (`D330_DISPLAY_RESUME=0` in `/etc/default/lenovo-d330-display-resume`) — it
  is strictly harmful now (unbind kills kwin; sddm restart leaves lit-black).
